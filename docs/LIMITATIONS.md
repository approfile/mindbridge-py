# 已知边界与演进路线

本文覆盖 MindBridge 当前实现的六类真实边界（并发与事务、认证与授权、安全策略深度、检索质量、工程完备性、产品化），每条给出「现状 → 风险 → 改进方向与优先级」，并附近期版本路线；前置阅读：[ARCHITECTURE](./ARCHITECTURE.md) 与 [SAFETY](./SAFETY.md)。语气按工程事实陈述，路线图不承诺具体日期。

---

## 1. 并发与事务

**现状**

- 调度循环是单进程顺序执行：「claim-based actor」体现在控制流语义，不是并发执行；
- 黑板用不可变结构重建，无锁，单进程安全；多 worker 下 `seed_data`、工具队列的 RUNNING 抢占都缺少分布式协调；
- 每条消息独立 `commit()`，没有跨步骤事务边界；`_dispatch_once()` 中「置 RUNNING」与「提交线程池」之间存在崩溃窗口（靠启动时复位兜底，但没有 lease / visibility timeout）。

**风险**：多实例部署时任务可能被重复执行或长期停留在 RUNNING；一次 run 的部分写入回滚不完整，trace 与报告可能不一致。

**改进方向与优先级（P1）**：为队列引入 lease / visibility timeout 与幂等键；用显式事务边界包住一次 run 的关键写入；把调度收敛到单一消费者，或引入跨进程协调。

---

## 2. 认证与授权

**现状**

- HTTP Basic Auth + SHA-256 无盐口令哈希；无 MFA、无令牌过期、无登录限流；
- 管理员 trace 接口可读取 `original_input` 原文与完整协作步骤；
- 演示账号与口令是种子数据，生产部署需要替换。

**风险**：口令泄露后果重、无法吊销会话；原文读取权限偏宽，需要最小权限与访问审计。

**改进方向与优先级（P1）**：替换为 OIDC / JWT，口令哈希升级为 bcrypt / argon2，补登录限流与会话过期；对 trace 中的原文读取做二次审计或只保留脱敏版本。

---

## 3. 安全策略深度

**现状**

- 安全审查是基于要素检查的规则审查，不是回复安全分类器；
- 风险词典为子串匹配，无否定检测（「我不想自杀」会被判 HIGH）；
- `PrivacySanitizer` 覆盖手机号 / 邮箱 / 18 位身份证号，未覆盖姓名、学号、住址、银行卡、微信号；
- 学生可见内容的元数据隔离依赖提示词声明与 SSE 禁用词断言，不是出口的结构化字段白名单；
- 工具策略门闸与审计只在 `TOOL_QUEUE_ENABLED=true` 的队列路径生效，MCP 直连路径绕过治理层。

**风险**：词典误报会产生不必要的干预；规则审查无法覆盖语义层面的危险细节；直连路径下策略与审计缺位。

**改进方向与优先级（P1）**：引入否定 / 假设 / 引用语境识别层；增加独立回复安全分类器与「危险细节」检测；在响应出口做字段级白名单；两条工具路径统一走治理层。

## 4. 检索质量

**现状**

- 重排是确定性公式而非学习型模型，无法理解语义相似但用词不同的表述；
- 60 条评测集只引用 11 篇内置文档中的 2 篇，无法反映全部知识库的检索质量；
- `Recall@K` 是二值近似（有任意相关命中即 1.0），不反映分级排序质量；
- BM25 每次检索全表载入内存，chunk 规模上量后需要倒排索引与缓存；
- 公开指标来自向量关闭的降级路径；完整混合检索尚未在同一评测集上复测登记。

**风险**：知识库扩展后检索质量缺少可回归的覆盖；词面检索对多要素组合问句存在系统性失败（当前 60 条中 2 条未命中）。

**改进方向与优先级（P2）**：评测集覆盖全部 11 篇文档与更多意图分支，引入分级相关性标注替代二值 Recall；知识库规模上升后替换为学习型重排（保留公式作为降级路径）；BM25 增加倒排索引与缓存；补一组向量开启的评测并把两组结果并列登记。

---

## 5. 工程完备性

**现状**

- 无 Alembic 迁移，建表依赖 `create_all`；
- 无结构化日志 / 请求 ID / Prometheus 指标；
- LLM 调用无重试与熔断；`ChatService` 中工具分派异常只记 warning，调用方不可见；
- MCP 工具服务基于 `mcp` 1.x 的 `FastMCP` API，因此 `requirements.txt` 将其限制在 `<2.0.0`；2.x 把入口改名为 `MCPServer`，直接升级会让工具服务启动即退出（聊天不受影响，但异常只在日志里）；
- 无覆盖率门禁、无 lint / type check 配置；
- 20 条路由中只有 2 条 `async def`，模型调用与 SQLAlchemy 访问是同步的。

**风险**：schema 变更没有可回滚路径；故障定位依赖人工看日志；静态问题只能靠测试兜底；同步链路限制单实例并发能力。

**改进方向与优先级（P2）**：引入 Alembic 迁移；补结构化日志、请求 ID 与基础指标；为模型调用加有限重试与熔断；CI 增加 ruff / 覆盖率门禁；逐步把模型调用与 DB 访问换成异步驱动。

---

## 6. 产品化

**现状**

- 前端为原生 HTML/CSS/JS，未做无障碍与移动端适配；管理端只有 4 个面板（风险个案、心理风险与咨询报告、RAG 知识库维护、会话档案），任务 / 死信 / 审计 / trace 只有只读 API，没有 UI 入口；未做响应式打磨（例如 1440px 宽度下个别按钮文案会换行）；
- `models/mindbridge-qwen2.5-7b-ft/` 只提供 Ollama `Modelfile` 与放置说明，不含 GGUF 权重（体积原因），需自行微调或下载；
- 完整工具闭环依赖执行路径：`TOOL_QUEUE_ENABLED=false` 时走 MCP stdio，未安装 `mcp` 时聊天与报告正常，但台账 / 个案 / 预警不会产生；`TOOL_QUEUE_ENABLED=true` 时队列路径可用；
- 演示账号、log 模式预警、单机部署都面向可演示与可审计，而非生产运维。

**风险**：作为对外演示时交互与视觉完成度有限；跨环境行为依赖依赖安装是否正确。

**改进方向与优先级（P3）**：补管理端任务 / trace 面板与响应式布局；提供多环境配置模板与部署文档；权重发布或改为托管推理；补齐前端基础可访问性。

## 7. 近期演进路线（3 个版本）

| 版本 | 主题 | 内容 | 验收口径 |
| --- | --- | --- | --- |
| **v0.1.0**（当前） | 可运行、可审计、可复现的首个公开版本 | 仓库呈现与文档拆分、LICENSE / CHANGELOG / Release、四张架构图、六个 docs 文档 | 文档链接全通；harness 6/6 PASS；23 个单测通过；`verify_offline.py` 33 项通过 |
| **v0.2.0** | 工程加固 | 否定检测与安全分类器接入、评测集扩到全部 11 篇文档、CI 增加 ruff / 覆盖率门禁、路由级回归补齐、`mcp` 2.x 迁移评估 | 新增安全回归断言；评测集覆盖全部文档；CI 门禁生效 |
| **v0.3.0** | 运维与并发 | Alembic 迁移、结构化日志 / 请求 ID / 指标、队列 lease 与 visibility timeout、鉴权升级（OIDC/JWT） | schema 可迁移可回滚；队列支持多实例安全消费；鉴权可吊销会话 |

优先级建议（与上表一致）：真实鉴权 → 事务边界与队列 lease → 否定检测与安全分类器 → 评测集扩容 → 迁移工具与可观测性。
