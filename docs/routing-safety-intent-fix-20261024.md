# 危险路由漏判与意图输出契约修复

日期：2026-10-24。本轮只处理危险路由漏判及意图输出契约，原100条标签、评分公式、模型名称、temperature和输出预算保持不变。更新已部署到本机 `http://127.0.0.1:8080`。

## 行为变化

- “无法保证自己的安全”不再被“安全”二字匹配成已经安全。当前不安全/安全不确定先进入澄清；有即时伤害动作或既往HIGH危机时升级HIGH。
- 危险上下文后的“我还是打算马上这么做”识别为危机延续，优先于短句含糊分支；无危险上下文时不据这句话强制判HIGH。
- 明确撤回行动、当前安全更新、技术意义的代码/账号安全单独处理；修复过程中还补回了“以前有自伤经历，但现在没有这个想法”的低风险边界。
- 只在已知危险历史下解释省略指代，当前明确伤害意图仍优先于安抚性词语；技术安全、假设和安全询问不作为“本人已安全”的证据。
- 意图模型统一返回 `{"intent":"CHAT|CONSULT|RISK"}`。角色提示与分类提示不再要求互相冲突的输出；OpenAI兼容请求使用JSON object模式，Ollama使用JSON格式。
- `intent_contract.py` 用同一schema严格解析枚举、唯一字段和重复键；不从任意解释文本中猜标签。异常仍会回退，但Trace明确记录source、degraded、reason、errorType和contract。
- `INTENT_JSON_MODE=true` 为默认值；若自定义兼容服务不支持JSON请求参数，可显式关闭该传输选项，提示和本地schema校验仍保持JSON合同。
- 评测改为读取真实intent artifact的source；不再用旧的纯枚举文本规则误判新JSON响应的来源。指标分母和评分公式没有改变。

第一次线上危机延续的正文，先后被审核判为缺少危机支持、包含后台标签，最终按既有机制返回固定安全模板和error。路由仍为HIGH/RISK，工具任务已持久化。相关Trace与日志保留；后续最终验收没有关闭或放宽出站审核来获取成功done。

线上路由验收区分“正文审核接受”和“固定安全兜底”。后者不代表意图解析失败，也不应被写成正常生成成功；验收脚本验证最终文本哈希及固定模板，并单独报告`allRepliesAccepted`。候选原文未外发，不据审核代码推断模型正文已经由人工确认违规。
