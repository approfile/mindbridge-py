# MindBridge 提升实施计划

更新：2026-11-01。
目标：国内大厂日常实习与秋招的大模型应用 / Agent 研发岗位。
最终产品支持用户自部署模型，或使用自己的云 API Key；训练可使用租用 GPU。
阶段 1、2 已于 2026-11-01 完成实现与验收，见[用量与缓存观测](MODEL-USAGE.md)与[系统基准](SYSTEM-BENCHMARK.md)；后续阶段仍为待实施路线。

## 顺序与依赖

保留当前基线 → 模型调用与成本观测 → 基准评测 → 双模式产品化与自部署基线 → 成本/性能优化 → SFT → GRPO 对照实验。
文档、演示和面试材料随每阶段更新。

## 阶段 0：保留现有可运行基线

- 归档当前源码、配置结构、语料版本与哈希，不归档或公开密钥。
- 保留 290 项单测、6 组 Harness、真实生成/向量/SQL/Redis/Excel/邮件的现有证据。
- 保留阶段开始时的缺口记录：线上 token/费用账本、缓存聚合指标当时未完成，现已由阶段 1 补齐；多用户模型配置现已实现，自部署模型真实验收与 SFT/GRPO 仍未完成。

验收：当前主链路可复现，后续每阶段都有同一口径的回归比较。

## 阶段 1：统一模型调用，补齐 token、费用与缓存观测（最先实施）

状态：已完成。321 项单测、6 组 Harness、真实 usage 抽查与管理面板验收通过；数值和限制见[阶段验收](MODEL-USAGE.md)。

先在现有接口上引入最小 ModelGateway，集中记录调用尝试和供应商响应，保持原业务行为。

- 按用户、run、角色、阶段、连接与模型版本关联每次请求；区分逻辑调用、HTTP 尝试和重试。
- 采集真实输入/输出 token、缓存命中/未命中 token、实际返回模型及请求 ID。
- 覆盖非流式、流式、审核与 embedding；流式末尾 usage 与正文分开处理。
- 按价格版本、币种与实际模型计算费用，汇总整轮及各阶段成本。
- 缺失 usage、断流和失败请求显式记录未知及采集覆盖率，不将未知写成零。
- 分别统计供应商前缀缓存、版本有效的 Redis 会话记忆命中、知识片段 embedding 复用。
- 未实现查询 embedding/检索结果缓存时不声明该能力；RAG 召回命中率不混入缓存指标。
- 元数据账本不保存 API Key、请求头或明文敏感对话。

验收产物：可追溯的模型用量账本、管理端或离线统计报告；抽查结果与供应商原始 usage 对齐。

## 阶段 2：建立质量、延迟、吞吐与成本基准

状态：已完成。335 项测试与 6 组 Harness；冻结 110 个场景试次、122 次真实 HTTP 请求、100 组独立评审，原始 JSON/CSV、源码快照和分账报告已归档。[正式结果与瓶颈](SYSTEM-BENCHMARK.md)。失败和 unknown 均保留，不代表系统质量全部通过。

基准暴露的可靠性问题已先完成修复与同数据集对照：342 项测试、6 组 Harness；完整 122 次 HTTP 中死锁由 10 次到 0，空证据契约从 2/12 到 12/12，修复前后均用 v3 评审器获得 100/100 有效裁决。原始失败和中间调试结果保留，见[可靠性修复](BASELINE-RELIABILITY.md)。自然任务仍有模型兜底，不代表业务质量全部达标；这不替代阶段 4 的成本/性能优化。

- 固定合成场景，覆盖 CHAT、CONSULT、RISK、长会话、证据不足、重试及异常。
- 测试 1/2/4 并发、超限请求、首次与重复请求；隔离测试账号和数据，避免清理实际业务缓存。
- 记录任务契约完成率、证据支持、恰当澄清/拒绝、回退率、重试率、完整 usage 覆盖率。
- 记录 P50/P95 整轮延迟、底层模型 TTFT 与最终审核后首个可见块延迟；分开统计。
- 报告每轮 token/费用、各角色成本占比、吞吐和缓存指标。
- 建库 embedding、在线请求、离线 judge、训练数据生成成本分账。
- 云端缓存以供应商返回为准，不将首次观测直接等同于完全冷缓存。
- 增加受控的简化编排对照，保持 RAG、安全规则与评审口径一致，分析多 Agent 的收益和开销。

验收产物：可复跑脚本、数据集清单、原始 JSON/CSV、汇总报告与主要瓶颈结论。

## 阶段 3：实现自部署 / 用户自填 Key 双模式

状态：双模式代码、模型设置页面与部署脚本已实现，离线/协议验收和真实云 API 能力探测通过；AutoDL RTX 5090 双模型、SSH 隧道、普通对话与咨询两轮合成业务冒烟已通过，见 [GPU 验证记录](SELFHOST-VERIFICATION-20261102.md)。**完整业务场景、双账号并发隔离、禁用外部模型 API 与同口径基准验收仍待完成**，阶段 3 尚未整体完成。本机 RTX 3060 Laptop 6GB 不作为正式 8B 性能基线。详见[双模式说明](DUAL-MODE.md)与[AutoDL 操作手册](AUTODL.md)。

在阶段 1 的 ModelGateway 上已增加部署连接目录、账号加密凭据、ModelProfile 与每轮固定配置快照。

- 用户选择供应商/模型、填写自己的 Key、测试连接后保存；凭据按账号加密隔离，接口返回掩码。
- .env 保留为部署默认值，不通过修改全局配置切换多个用户的 Key。
- 自部署主服务优先验证 vLLM，个人体验可支持 Ollama；统一完成流式、JSON、上下文和 thinking 输出能力检查。
- 自部署模式覆盖实际运行的所有模型依赖，包括生成、理解、安全、审核、改写、摘要和 embedding。
- 全本地模式不隐式回退到云端；云模式的聊天和 embedding 独立配置。
- embedding 索引按知识库作用域、语料版本、模型/连接版本、维度及切块配置绑定，新索引验收后切换。
- 集中托管服务连接的是可达的自部署端点，不将访问者浏览器的 localhost 当成服务器可访问地址。
- 接入一个未微调的 8B 级候选模型，建立自部署原始基线；依据实际任务和试运行再选训练规模。

验收产物：两种模式走相同业务契约；两个账号并发不串凭据；完整本地模式可在禁用外部模型 API 的条件下运行。
按阶段 2 口径比较云 API 与自部署模式，自部署成本包含 GPU 时长、利用率和吞吐。

## 阶段 4：根据实测瓶颈做性能和成本优化

- 优先处理阶段 2/3 成本占比或关键路径占比最大的部分，不预先假设哪个 Agent 必然最贵。
- 候选优化包括稳定提示词前缀、按需上下文与 RAG、受限记忆压缩、embedding 复用、小模型分工和并发调度。
- 缓存绑定用户/知识库作用域、模型与索引版本；不直接跨用户复用心理对话结果。
- 记录优化前后效果；不能用省略必要审核造成的质量下降来冒充系统效率提升。

验收产物：至少一项可归因的优化对照，展示费用/延迟/吞吐变化，同时报告任务质量、边界和失败变化。

## 阶段 5：构建数据，进行 SFT 并部署验证

- 从固定基线中的真实错误归纳目标，优先证据遵循、澄清/有限回答、表达边界与指令遵循。
- 使用合成或获授权的数据；业务 trace 与训练导出分开，保留来源、审核和版本信息。
- 按场景 family 去重划分训练、验证与测试，另建未用于开发/调参的测试集。
- 固定基座、tokenizer、chat template、训练配置与随机种子，使用独立训练环境和租用 GPU。
- 保存 adapter/checkpoint、训练日志、数据哈希与模型卡，导出到自部署推理服务。
- 比较同基座原始模型、提示词改进和 SFT；固定 RAG、工具、安全、预算与评审条件。

验收产物：真实可加载的训练产物、可复现实验和上线模型；用未见测试集说明 SFT 的收益及代价。
基础模型候选详见模型演进方案；8B 是首个正式试验规模建议，不是预设最优模型。

## 阶段 6：进行小规模 GRPO 对照实验

- 先分析 SFT 后剩余错误及奖励是否可验证，再确定任务。
- 可探索证据约束回答和澄清决策；若扩展到多步检索/工具动作，先建立受控环境和真实执行反馈。
- 奖励同时考虑任务达成、证据支持、边界与成本，检查奖励投机、奖励方差和训练稳定性。
- 比较 SFT 与 SFT + GRPO 在未见测试集的结果；训练奖励上升不等于业务效果提升。
- 若收益明确再扩大训练投入并部署；退化、无收益及失败分析保留在报告中。
- 仅在模型动作、环境反馈、多步轨迹和训练闭环均实际完成后使用 Agentic RL 表述。

验收产物：奖励代码、训练曲线、checkpoint、独立测试与失败分析；最终模型选择有证据支持。
