# 安全与数据边界（当前版本）

风险判断结合规则、严格结构化模型结果与兜底；高风险覆盖普通路由，正常生成必须等待风险评估。规则命中不是校准后的概率，模型自报把握也不是风险概率。

计划审核只检查准备好的消息与证据结构。实际候选正文还有来源分隔、规则审核、独立模型审核、最多一次修订及固定兜底；不能将计划 approved 当正文已安全。详见[正文审核](reply-safety-review-v2.md)、[路由契约](routing-safety-intent-fix-20261024.md)。

SQL 与 Redis 敏感正文加密；默认管理列表只提供去标识元数据。ROLE_ADMIN 不自动获得 ROLE_SENSITIVE_READER；敏感详情需要单独权限与用途，访问落审计；原始输入不通过 HTTP 接口返回。审计读取使用独立角色。保留清理默认预览，删除须显式离线执行。[敏感数据治理](privacy-governance-20261025.md)。

当前仍有单人抽检发现的回复充分性/安全边界分歧，以及记忆与路由反例，见[评测](BENCHMARKS.md)。项目未通过临床有效性或安全认证。密钥文件、历史备份、组织与个案级权限、外部 API 数据条款仍是部署边界，不因字段加密而自动解决。
