# P0 / P1 五项缺口改进（2026-10-31）

本轮修改业务源码，并使用原冻结标签回归。新结果与 2026-10-28 的分层主评测分开保存，不覆盖历史成绩，也不将本轮专项成功率替换成完整 Agent 成功率。

## 1. 会话事实：只采纳明确陈述，并重建旧派生状态

- `memory_facts.py` 集中处理字段白名单、明确陈述、纠正与遗忘，排除问句、假设、示例及他人归属；不从 assistant 消息提取。
- 统一中英文键名，去掉英语句末点号，保留 v1.2、.NET、1.5 等内部标点。
- 纠正、遗忘、多次赋值按消息内实际顺序执行。
- `SessionMemory.state_json` 增加 `extractorVersion=2`；旧版、损坏或来源无效的派生状态，在下一次会话读取时从该用户该会话原始 USER 消息重放。保留原聊天，不做全库原文重写。
- 这是有界字段抽取，无法声称支持任意自然语言事实。遇到含糊表达宁可不提取；已知问句污染与英文点号反例已有回归。

## 2. 危险否认与咨询诉求分离

`UnderstandingAgent` 在 `negated_only` 分支同时检查当前个人困扰/支持诉求。明确安全或否认危险不再直接压过“作息、烦躁、紧张、想聊聊”等咨询信号。风险等级仍由原独立安全流程判定，普通任务、文学/学术引用继续保留独立边界。

原 Agent 场景 normal-05、normal-07、normal-10、evidence-08、recovery-02 的输入未变，新增测试同时核对其 CONSULT/LOW 结果；并保留危险否认后的 Python 学习、学术主题等 CHAT 对照。

## 3. 高风险正文与完成声明

- 策略升级为 `reply-safety-v3`。高风险保护动作不再由“安全最重要”这类口号单独满足；规则仍不能识别全部自然表达，允许已有的语义核验分支，但必须引用实际候选正文。
- 高风险固定兜底补充具体保护行动、现实支持、即时危险的紧急服务引导和简短安全确认问题。按当前输入提供中文/英文兜底，不提供猜测的热线号码。
- 扩展中英文主动/被动完成声明筛查，例如已预约、系统已提交、I've notified、appointment has been confirmed。保留否定、条件说明和对用户自己已采取行动的正常回应。
- 这仍是规则与模型联合审核，不构成对任意表达的完备安全证明；新兜底尚未重新取得专家或用户盲审评分。

## 4. 生成 / 审核的预算内传输重试

仅包裹正文生成与正文审核的模型请求，不重放报告事务或工具任务。

| 项目 | 策略 |
| --- | --- |
| 默认尝试次数 | 最多 2 次，可配置 1–3 次 |
| 可恢复错误 | httpx 超时、网络/远端协议错误、HTTP 408/429/500/502/503/504 |
| 不重试 | 余额/鉴权/参数错误、非法审核 JSON、正文违规、token 截断、取消或整轮停止 |
| 等待 | 指数退避；尊重 Retry-After，不为了塞进预算而缩短服务端要求的等待 |
| 时间约束 | 所有尝试共用原回复截止时间与整轮预算；剩余时间不足直接兜底 |
| 部分生成 | 丢弃失败尝试的全部缓冲，不拼接、不提前 SSE 暴露 |
| 审核重试 | 复用同一候选，不重新生成正文 |
| SSE EOF | OpenAI-compatible 流未出现完成标记/stop 时视为协议中断，避免把干净 TCP EOF 当完整回复 |
| 审计 | `model_retry` 事件记录阶段、次数、类别、状态和等待，不记录密钥或异常正文 |

重试可能增加供应商计费，不能保证断连后上游立即停止计费。

## 5. 查询预算与正文证据核验

- 正常改写不再截取前 60 字符，默认预算 1024 字符。模型超长输出拒绝采用并显式回退原输入；超长原输入按首尾窗口选取、保留省略标记，并记录 `truncated/head_tail_window`，不宣称无损。
- Context 改写提示要求保留否定、时间和当前需求，避免新增症状、诊断或机构事实。
- 生成侧接收有边界的参考资料 JSON，明确资料是数据，不是角色或审核指令；具体事实与方法须有资料支持，共情不必伪装成知识库事实。
- 对有 RAG 参考的候选正文，审核必须逐句覆盖 `candidateSentences`，将句子区分为支持表达、用户事实、检索事实或未支持内容。
- 检索事实只能引用本轮 R 来源；用户事实只能引用 USER 消息或有来源的会话事实。来源 ID、连续引文及覆盖/重复情况由代码检查；空泛的 approved 不能跳过这些检查。
- 机制、因果、数值与校规断言不能通过标成共情绕过证据。若模型本来批准正文但误标来源类型，允许对同一候选澄清一次：补齐真实来源或拒绝；不修复非法 JSON，不覆盖安全拒绝，不重置预算，也不修改候选正文。
- 文本预算外的 chunk 不获得来源信用，摘要哈希基于实际纳入的内容。审计保存句子分类、来源 ID 与引文哈希，不重复存储引文正文。

**限制：**代码能核对覆盖与引文归属，不能单独证明语义蕴含。模型仍可能误分类或误判支持关系；缺证据后的拒绝/兜底也会影响回复可用性，需要独立评测与人工复核。

## 验证与新旧结果

本轮验证分开记录：

- 离线单测与工程 Harness。
- 当前 DeepSeek 的 100 条意图、28 条上下文边界、80 条冻结候选安全审核，各一轮。
- 独立 SQLite/Chroma 的实际 HTTP 对话：新旧记忆状态、五类路由、中文/英文风险响应；直接读取 SQL、工作簿和审核哈希。
- 同一冻结 12 题 RAG 组件的新生成与 RAGAS，参考答案未传给生成侧。

最终数值、覆盖率、失败与源文件哈希见 [本轮汇总](benchmarks/p0p1-hardening-20261031-summary.json)。已知开发集上的回归不能当独立盲测，单轮变化不构成严格因果消融。

首次边界采集因独立夹具密钥未初始化，在模型调用前失败；失败记录保留，使用已初始化的独立评测密钥重新采集。mock 的词典桩不能覆盖真实模型语义，因此 mock 分数不冒充真实模型分数。

## 配置

新增配置均有默认值：

```env
KNOWLEDGE_QUERY_MAX_CHARS=1024
REPLY_REVIEW_MAX_TOKENS=1024
MODEL_TRANSPORT_MAX_ATTEMPTS=2
MODEL_RETRY_BASE_DELAY_SECONDS=0.25
MODEL_RETRY_MIN_REMAINING_SECONDS=0.5
```

正文审核上限增加是为了容纳逐句来源记录；回复本身的生成上限与整轮截止时间不因此放宽。旧 v1 任务/指标契约、知识语料和标签保持不变。

第一版实测暴露“大脑执行功能像被调低”等无来源机制解释被评审误标为共情；第二版增加类型检查后出现来源分类误拦；第三版只对原本批准但违反来源类型契约的同一候选澄清一次，仍需真实来源引文。三阶段均保存，未挑最佳重复，也未修改问题/参考答案。

这些是已见工程题上的迭代观测，生成与评审有同源偏差，存在模型随机性；不能据此将变化全部归因于一个改动，也不是临床准确率。原 75 试次 Agent 分层报告和人工表未重新运行或重填。
