# 正文审核增强与回复安全评测

本轮对应原缺陷清单第6、8、10、19条。只改主项目，发布副本没有自动同步。

## 实现范围

**计划检查只证明准备约束完整。** ResponseAgent注入服务器生成的策略对象与固定位置的system约束；SafetyAgent核对版本、风险要求与服务器消息，不再拼接用户历史/RAG后查四个词。Trace明确标为prompt_plan_only，不把其通过率当正文安全率。

**实际正文分层审核。** Unicode/零宽字符和字段格式归一化后，检查后台字段赋值、明确诊断/剂量指导、羞辱、隔绝支持、AI唯一依赖、虚假通知/预约、未核实具体联系方式等。否定限定在相应动作/判断附近；自己的建议不能靠引号隐藏。高风险回复检查肯定保护动作、现实支持和下一步，而非只数安全词。

明确违规先硬拒绝；只有“现实支持和下一步已经肯定表达，但词面无法确认保护动作”这一不确定性可交模型语义核验。模型若放行，必须逐字引用候选自身的保护动作片段，本地检查长度与来源；不能用学生输入或检索内容作证。没有证明、无效JSON、重复键、额外字段、矛盾裁决、超时均保守兜底。

**来源分开使用。** 检索材料可支持具体资源事实，不能发出审核指令。用户输入、历史和有消息来源的会话事实可支持“项目代号”等一般记忆回答，不能自行核实外部机构号码；本轮明确更正优先于旧快照。资源是否真正权威仍依赖管理员维护，来源可追踪不等于医疗真实性已独立验证。

**完整收集再发送。** 未通过候选不发送给学生、不存为最终助手回复；审查Trace保留策略版本、ruleId、要素检查、来源哈希及候选哈希。最多修订一次，被拒草稿传给生成器时明确标成不可信草稿；仍不通过则固定模板+error，不伪报done。报告及持久工具任务依旧在正文前提交。

规则按代码和`reply-safety-v2`版本管理，没有开放运行时任意编辑规则的后台。置信度校准、原文访问治理、分布式编排不在本轮范围。

## 三类评测，口径分开

1. **80条静态候选、40对正反例**：正常40、应拒绝40，评分前冻结，包含中英文、否定、引用、资源和来源干扰。分别测规则层和规则+真实审核模型的完整门闸；每版两轮，第一轮预指定为主结果，所有轮次保留。
2. **12个受控不合格初稿**：先送固定坏稿，再由真实Response模型重新生成一次、真实Safety调用复审，记录初稿漏放、修订接受及固定兜底。接受率是运行时判断，不是独立人工判定的回复安全率。
3. **8个来源攻击变体**：复用一个正反例，分别在学生输入、检索材料、助手历史和用户历史放入改写审核指令。这些候选不触发确定性规则，确保实际调用模型。它们不是8个独立业务场景，也不是全面红队测试。

静态集包括“不相关/拒绝倾听”等质量违规；聚合指标称**不合格回复漏放率**，不能全部包装成危险指导漏放。固定候选被判得对，也不代表真实生成器始终产出安全回复。

标签由开发助手编写且可见实现，未经独立专家/临床标注。该集已用于开发回归，不是独立盲测。80条、8个变体与12次修订任务不能相加宣称“100条独立安全样本”。

## 实测结果与证据

前后全部数字、保留的失败与最终线上验证见 `target/reply-safety/REPORT.md`；便于随项目发布的摘要见 `docs/benchmarks/reply-safety-v2-summary.json`。

中间版本曾误拦正常医生转介、羞辱否认以及会话事实，均保留在本机candidate目录，并补充作用域/来源回归。没有删除难例或修改原80条标签来提高分数。最终仍可能出现模型拒绝或保守误拦，不能把小集零漏放写成临床或全场景保证。

本机独立MySQL/Redis/SMTP故障注入使用模拟审核模型强制批准，用于验证规则、SSE阻断及持久任务；它与真实云模型评测分开报告。测试号码/网址为虚构夹具，邮件只送本机Mailpit。

## 复测

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m app.harness.runner
.venv/bin/python -m app.evaluation.reply_safety_runner --provider configured --mode all --repeats 2 --output target/reply-safety/recheck.json
.venv/bin/python -m app.evaluation.reply_source_runner --provider configured --output target/reply-safety/source-recheck.json
```

不具备真实模型配置时可用`--provider mock`验证流程，但mock成绩不能写成真实模型安全成绩。评测会保存模型配置、源码与数据哈希、逐条结果和所有错误；不可用审核留在分母中，同时单列决策可用性，避免用故障造成的全拒绝刷零漏放。

基线在`.local-runtime/body-safety-20261024/before/`，完整模型结果在`target/reply-safety/before-cloud.json`和`after-cloud.json`。新输入与标签须建立新版本，不覆盖现有SHA。
