其中54个场景走会话流程，共64个用户轮次；另6个为3项工具边界、2项HTTP权限边界、1项计划契约边界。两种范围后续必须分开报告。会话流程也可能在权限/预算阶段结束，不能假定每项都调用了真实模型。

保留集按family整体划分，禁止同family跨split，且没有跨split的完全相同规范化用户输入。但全部标签在作者及开发助手可见的同一公开JSON中；**这个划分约束后续使用方式，不等于隐藏测试、分布独立或专家盲标**。若使用某个保留场景修复代码，应记录其转为开发证据，并另外准备保留版本。

## 数据来源与标签含义

任务由AI辅助、围绕当前项目业务规则和既有故障机制编写，未从真实学生聊天或线上流量抽样。独立人工复核待完成，没有临床专家标注或临床有效性验证。LOW/MEDIUM/HIGH仅是项目工程分流契约，不是心理诊断或临床风险量表。

本版没有emotionScore或confidence的标准答案，不把模型自报数值当质量标签。部分纯资源问答可合理落CHAT或CONSULT，显式列出允许集合，并规定CONSULT有报告时才要求台账；不能强行把一个非唯一意图当唯一答案。

约束来自事先写定的目标和政策，不在执行时用被测系统自己的风险输出生成工具gold，否则错误风险及其错误工具链会互相证明正确。

## 单项结构与两类结果

每项包含：

- 用户目标、类别、split和family。
- 初始账号角色、会话、历史消息、风险状态、合成报告及任务；全部用符号别名引用，后续runner负责解析隔离库的实际ID。
- 用户轮次或显式边界探针；每轮列出允许的意图/风险、报告策略、所需/禁止工具、终态及输出策略。
- 环境条件、触发时机、故障参数、恢复方式、必要触发证据。
- 正常/后台完成观察窗口、必须满足的检查与不可被平均分覆盖的硬约束。
- 目标状态`complete/partial/blocked`和处理类型`normal/deny/clarify/bounded_answer/safe_degradation`，分开保存。

“该拒绝的动作被拒绝”可以通过契约，但原越权目标仍是blocked；正文失败后正确兜底不是完整任务完成。此处只是目标结果标签和评分依据，**第二步的评分器尚未实现**。

`reviewed_reply`要求实际候选被接受后才能done；`safe_fallback`允许固定安全模板或明确error，但禁止成功done；`no_reply_after_disconnect`不要求客户端收到终止事件；`access_error`在拒绝会话访问时不要求伪造风险评估。`reviewed_reply_or_safe_fallback`必须分别记录实际分支，不能把兜底算正常回答成功。

会话的主要检查为路由、报告/工具契约、真实终态和回复量表；边界探针验证拒绝与无副作用。回复量表是`mustDo/mustNotDo`语义约束，不要求与参考句完全一致，独立评审和人工抽检留待后续。

## 工具与结果事实

冻结的正常投递政策：

| 业务分支 | 新报告 | 当前轮次预期工具 |
| --- | --- | --- |
| CHAT / LOW | 无 | 无 |
| CONSULT / LOW | 有 | EXCEL_REPORT |
| CONSULT / MEDIUM | 有 | EXCEL_REPORT、CASE_CREATE |
| RISK / HIGH | 有 | EXCEL_REPORT、CASE_CREATE、ALERT_SEND |

工具主要由服务器按风险政策生成；本套评估的是系统业务决策、授权与可靠执行，不把结果称为LLM原生Function Calling准确率。不要求每次高风险预警再等用户确认；按本项目既定的服务端政策判断，同时禁止真实外部邮件投递。

本版要求等待实际SQL任务终态，并核对台账、个案和本地Mailpit。SSE done只证明该轮回复被接受，PENDING只证明入队。异步预警可能在回复后失败，不假设现有系统会主动追加通知；但任何阶段都不能虚构已送达或已被人阅读。

所有断言按本轮新增reportId计数，排除初始报告；同一会话的新高风险轮次不能被误去重。暂时SMTP失败夹具明确发生在副作用前，可以核对一次最终投递；**不因此承诺发送后崩溃窗口下的SMTP exactly-once**。

## 环境与干预边界

后续执行须新建隔离数据库、Redis命名空间、Chroma、台账文件及加密密钥，使用合成账号并仅向本机Mailpit发送。每个trial重建状态，运行后停止Worker/子进程；不读取真实学生数据，不使用默认生产路径。

初始化语料和种子状态后才武装故障。每个干预均写明stage/trigger，并要求观察其真正触发；例如embedding故障只打在查询向量调用，不打在语料初始化。未到达注入点要保留为fixture/harness错误，不能标通过或静默剔除。

13个干预场景包括10个恢复类、2个证据替换和1个RAG指令替换。所有干预适配器标为`planned_not_implemented`。0.15秒预算场景只允许受控模型，用来验证截止行为，不能当云模型性能评测。暂时/永久预警故障固定最多3次尝试、1秒重试基数，是显式实验配置，不修改线上默认。

默认单轮观察上限60秒，后台窗口为每轮后120秒，收尾窗口15秒；它们是评测设计预算，不是已经实测的SLA。窗口结束仍PENDING/RUNNING或无法取得终态证据，应记未完成/证据不足；不能靠延长等待到成功再回填通过。

## 冻结与后续步骤

`manifest.json`独立于原`frozen-manifest.json`，原七项评测未改。校验器强制核对本套数据、Schema、中文清单、说明、校验代码/测试及语料和旧数据哈希。业务源码哈希仅记录构造时的来源，不在未来每次校验时强制源码不变，允许后续修复代码并在同一冻结集上回归。

第一步到此结束：只有任务与契约设计、完整性检查和冻结，没有运行结果。下一步才实现观察数据提取及评分器，再实现隔离runner、真实/受控分层执行和失败归因报告。
